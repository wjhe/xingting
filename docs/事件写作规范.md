# 《问道长生》事件写作规范

写新事件时照这份规范做（人和 AI 都适用）。写完必须跑一遍内容校验：

```bash
npx vitest run tests/content.test.ts
```

---

## 一、文件与格式

- 事件按批次和区域分文件放在 `src/data/events/`，**新文件要在 `src/data/index.ts` 的 `EVENT_FILES` 里登记**。
- 字段定义见 `src/core/types.ts` 的 `EventDef`。写法可以参照现有文件，例如 `src/data/events/mountain_m2.json`。
- 事件 id 用小写英文加下划线，前缀用区域：`village_`、`mountain_`、`market_`、`valley_`、`yunmeng_`。id 全局唯一。

### 字段速查

```jsonc
{
  "id": "mountain_xxx",
  "title": "四字以内的标题",
  "region": ["luoxia_mountain"],          // 出现的区域，可以多个；不写表示只能被 next 串联触发
  "weight": 6,                            // 出现权重，普通事件 4～8，稀有 2～3，剧情节点 10～30
  "once": true,                           // 每世只触发一次（剧情、奇遇用）
  "conditions": { "realm_min": "lianqi", "flags": ["xxx"] },
  "art": "mountain_wolf",                 // 插图，必须从第五节的插图列表里选
  "text": "事件描述",
  "options": [ /* 2～3 个选项 */ ]
}
```

选项有三种：
1. **直接结果**：`{ "text", "result", "effects" }`
2. **属性检定**：`{ "text", "check": { "attr", "dc" }, "success": {...}, "fail": {...} }`
3. **战斗**：`{ "text", "result"（开战前的一句话，可选）, "battle": { "enemy", "win": {...}, "lose": {...} } }`

选项还可以加：
- `requires`：不满足时按钮置灰。可以要求灵石、物品、标记，例如 `{ "stones": 100 }`、`{ "items": { "wolf_pelt": 3 } }`。
- `next`：触发后续事件，用来做事件链。

### 效果类型（effects）

| type | 写法 | 说明 |
|---|---|---|
| cultivation | `{ "type": "cultivation", "value": 100 }` | 修为，可以为负 |
| lifespan | `{ "type": "lifespan", "value": -3 }` | 寿元（年） |
| attr | `{ "type": "attr", "key": "wuxing", "value": 1 }` | 属性：gengu 根骨、wuxing 悟性、shenshi 神识、jiyuan 机缘、xinjing 心境 |
| item | `{ "type": "item", "id": "herb_qingling", "count": 2 }` | 物品，可以为负（要配合 requires） |
| stone | `{ "type": "stone", "value": 50 }` | 灵石 |
| hp | `{ "type": "hp", "value": -30 }` | 气血，按上限的百分比，范围 -100～100 |
| break_bonus | `{ "type": "break_bonus", "value": 0.05 }` | 下次突破成功率加成 |
| flag | `{ "type": "flag", "key": "xxx" }` | 本世剧情标记 |
| meta_flag | `{ "type": "meta_flag", "key": "xxx" }` | 跨世标记（**只有主线和人物羁绊才用**，新增前先和主策划确认） |

## 二、文风

- **古风白话**：像修仙网文的叙述，不是文言文。句子简洁，有画面感。
- 描述 **2～4 句**（40～120 字），结果 **1～2 句**。
- 用第二人称"你"。
- **禁止**：现代用语（"OK""手机""效率"之类）、网络梗、真实宗教的神佛名号和教义、血腥细节、色情暗示、对现实迷信行为的宣扬。
- **结果文案必须和效果一致**：写了"获得一株灵草"，effects 里就一定要有对应物品；没有给的东西不要写"得到了"。
- 选项要是**有意义的取舍**：冒险与保守、善与恶、花钱与省钱，不要出现明显的"送分选项"。
- 好的事件会有一点**人情味或意外**：反转、余韵、小幽默。

## 三、数值参考（按推荐境界）

| 境界 | 灵石奖励 | 修为奖励 | 寿元损失 | 检定难度 dc | 可用敌人 |
|---|---|---|---|---|---|
| 凡人（青石村） | 5～40 | 10～30 | 1～2 | 6～9 | village_thug、wild_boar |
| 炼气（落霞山） | 20～150 | 30～200 | 1～5 | 5～9 | black_wolf、bandit、mountain_monkey、poison_spider、blood_bats、fox_spirit、rival_lianqi |
| 炼气、筑基（青云坊市） | 50～800 | 100～800 | 少用 | 6～9 | 一般不打架 |
| 筑基（黑风谷） | 200～1500 | 300～2000 | 3～15 | 7～10 | bear_demon、rogue_cultivator、corpse_puppet、red_python、evil_cultivator、sect_enforcer |
| 金丹（云梦泽） | 2000～8000 | 5000～30000 | 10～40 | 8～11 | jiao_dragon、demon_cultivator、thunder_roc、tree_demon、demon_elder |

| 元婴（北冥海） | 1 万～10 万 | 10 万～100 万 | 20～80 | 10～13 | jiao_guard、sea_witch、kun、rogue_immortal、shen_dragon |
| 化神（昆仑墟） | 10 万～100 万 | 100 万～800 万 | 50～200 | 11～14 | sword_spirit、luwu、kaiming、heaven_demon |
| 渡劫（昆仑墟） | 50 万～500 万 | 500 万～5000 万 | 100～300 | 12～15 | heaven_demon、demon_patriarch |

- 境界高了，属性也会被事件慢慢加到 10～15，所以高境界的检定难度可以到 13～15。
- 检定：d10 + 属性 ≥ dc 即成功。初始属性 1～10，所以 dc 8 对普通角色大约 30%～70% 的成功率。
- 物品见 `src/data/items.json`，敌人见 `src/data/enemies.json`。用之前先看价格和描述，奖励的物品价值要和境界相称。
- 境界条件用 `conditions.realm_min` / `realm_max`，避免低境界角色碰到高境界的敌人。
- 战斗事件**一定要给一个不打的选项**（逃跑检定、花钱、绕路等）。
- **可重复事件**给的物品，按卖价（定价的一半）算不能超过该境界灵石上限的 2 倍，否则会被反复刷钱。贵重物品只放在 `once` 事件里。校验会自动检查。
- **低境界闯高级区域**的事件（比如炼气去黑风谷）要设 `once`，奖励按玩家当前境界给，不能按区域给。

## 四、标记约定

- 本世标记（flag）用于事件链：前一个事件设置标记，后一个事件用 `conditions.flags` 要求它。
- 每个被条件引用的标记，都必须有事件设置它，否则校验会报错。
- 已有标记不要重复使用在别的意思上。各批次的标记前缀：`low_`、`mid_`、`high_`、`p4_`（人物线）、`r4_`。新批次请用新前缀。现有标记：`fox_saved`、`heard_ruins`、`heard_taichu`、`letter_done`、`lihan_*`、`promise_letter`、`su_*`；跨世标记：`heard_yunmeng`、`met_old_man`、`old_man_truth`、`ruins_mural`、`su_bond`、`truth_known`。

## 六、写完自查

- [ ] 跑 `npx vitest run tests/content.test.ts`，全部通过。
- [ ] 每个结果文案都和 effects 对得上。
- [ ] 战斗事件有不打的选项，敌人强度和境界条件匹配。

## 七、天材地宝与突破（第一期新增）

- 物品类型 `treasure` 是突破用的天材地宝，**不能出售**，只在事件里获得。
- 各境界突破所需：
  - 金丹→元婴：化婴丹 = `jiao_nilin` 蛟龙逆鳞 + `lian_xin` 千年莲心 + `roc_jingpo` 雷鹏精魄（云梦泽）
  - 元婴→化神：化神丹 = `kun_feather` 鲲鹏羽 + `xuanbing` 万年玄冰 + `haiyan_pearl` 海眼灵珠（北冥海）
  - 化神→渡劫：渡厄金莲 = `busi_seed` 不死树种 + `kunlun_jade` 昆仑玉髓 + `tianlei_stone` 天雷石（昆仑墟）
- 天材地宝可以出现在**可重复**事件里（不计入刷钱校验），但要有代价：强敌、高难度检定、或者折寿。
- `realm_up`、`qi_deviation` 两个效果只在心魔事件里用，普通事件不要用。
- `unstuck`（打破小境界瓶颈）只用在 `conditions.stuck: true` 的顿悟类事件里。

## 八、去重与属性（2026-10-26 新增）

- 引擎会记住最近 8 次历练抽到的事件，刚遇过的很难再遇到。所以可重复事件不必为了"别太常出现"而刻意压低权重。
- **可重复事件给的属性，每世只在第一次生效。** 同一事件再做一次，属性不再增长，日志提示"没有再长进"，其他奖励照发。写可重复事件时可以照常给属性，但不要把属性当作这类事件的主要回报。
- 多世专属事件用 `conditions.life_min`。跨世伏笔用 `meta_flag` 设置，标记前缀跟随文件（如 `e2c_`）。要避免同一世里既埋伏笔又收回：埋的那一步再设一个本世标记，收回的事件用 `not_flags` 排除它（参考 `src/data/events/e2_lives.json`）。

## 九、冲关外扰事件（2026-10-26 新增）

- id 以 `break_disturb_` 开头、不填 `region` 的事件，会在闭关冲击大境界时由代码随机抽取（见 `src/data/events/p3_break.json`）。可以用 `conditions` 限定境界。
- 结果主要用 `break_bonus` 增减这次冲关的成功率（可为负，-0.15～+0.15 为宜），也可以扣气血、加属性。
- 不要用 `next` 串联到普通事件，也不要设置 `realm_up` / `qi_deviation`：冲关的成败由代码掷骰决定。
