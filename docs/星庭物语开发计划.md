# 《星庭物语》开发计划

更新日期：2026-11-01  
状态：开发推进中，实际完成项与验证结果见 [开发推进记录](stargarden/开发推进记录.md)。以下保留计划基线，计划条目不代表已经完成。

## 1. 产品目标与现状

制作适合手机竖屏游玩的原创女儿养成游戏，参考《美少女梦工场2》的成长节奏、日程安排、服装购买与主界面展示体验。人物、世界观、剧情和素材保持原创。

核心体验：玩家陪伴女儿从 10 岁成长到 18 岁，通过课程、工作、家庭交流、探索和选择，形成不同的性格、关系与人生结局。美术采用已确认的明亮、干净、清新赛璐璐画风，音乐温暖耐听。

制定本计划时，网页 Alpha 已有 96 个月成长、18 种活动、六项能力、压力与亲密度、20 个生活事件、探索交锋、11 种结局、存档与衣橱。当时素材仅覆盖部分场景、两个年龄立绘及同一裙型三色；界面仍偏网页，剧情连续性、活动配图、真正的衣装款式和音效均需扩充。

现有实现见 [开发说明](星庭物语开发说明.md)，画风基准见 [美术规范](星庭物语美术规范.md)。旧《问道长生》的事件写作规范不直接适用于本作，本阶段另建专用剧情规范与数据定义。

## 2. 已确认的需求

| 方向 | 实施要求 |
|---|---|
| 界面 | 减少网页式卡片、空白和细线图标，建立经典养成游戏的绘制感界面 |
| 图片 | 上课、工作、事件、探索、战斗、节庆与结局都有相应视觉表现 |
| 换装 | 玩家买衣服、衣橱选择、主界面展示；服装有真正不同款式与年龄版本 |
| 抠图 | 评估成熟 AI 前景分割方案，修边并验收，替换正式素材的临时图割流程 |
| 剧情 | 八年成长主线、角色支线、大量条件触发事件，选择影响后续内容 |
| 声音 | 查找明确标为 CC0 的音效，建立来源记录；提供 AI 音乐需求与提示词 |
| 平台 | 先完善竖屏网页版本，再单独规划 Android 等平台适配 |

## 3. 界面与演出改造

主界面以房间和女儿立绘为主体，时间、金币、状态和操作围绕画面组织。用有绘制感的边框、纹理克制的面板、实体按钮与图形菜单取代通用网页组件，同时保持触屏可读性。

- 主界面：突出人物、当前穿着、年龄和心情；常用操作无需长距离滚动。
- 日程：采用月历与日程格，活动使用统一图标或小插画，清晰显示费用和预期影响。
- 商店与衣橱：支持款式预览、价格、已拥有状态、适用年龄与穿着反馈。
- 剧情：背景、人物、表情和对话框构成主要画面；关键段落切换专属插画。
- 战斗：显示环境、敌人、角色战斗形象、动作反馈与结果演出，延续现有自动交锋规则。
- 手账与结局：使用成长相册、事件记录与结局插画，呈现玩家的培养过程。

竖屏基准为 390 像素宽，同时验收 320、375、430 像素宽和桌面竖屏展示。按钮可触达，文字不被装饰遮挡，刘海与底部安全区留出空间。

## 4. 美术素材规划

### 4.1 分层规则

显示顺序以“背景 → 人物/敌人 → 服装与配饰 → 特效 → 对话与操作界面”为基础。普通事件复用背景和表情，重要剧情用专属插画。所有人物层统一画布、脚底基线、锚点与缩放规则。

复杂裙装可制作整套透明人物立绘，保证袖子、手臂与裙摆关系正确；适合拆分的衣服再分为前后衣片、身体和配饰。不能只靠抠图自动还原被衣物遮住的身体，也不能将改色统计成新款式。

### 4.2 首轮内容预算

以下为制作目标，具体素材按剧情与界面需求登记，允许复用，不机械地为每个事件生成一张新图。

| 素材 | 首轮目标 |
|---|---|
| 年龄体型 | 10–13、14–15、16–18 岁三个阶段 |
| 基础表情 | 每阶段至少 6 种：平静、开心、害羞、难过、生气、疲惫 |
| 服装 | 每阶段先做 4 款，合计 12 套年龄适配立绘；配色变体另计 |
| 常驻背景 | 约 8–12 张，覆盖家园、城镇、学校、工作地点与探索区域 |
| 活动插画 | 约 8–12 张，优先覆盖高频课程和工作 |
| 关键事件插画 | 约 12–16 张，服务主线转折、生日与节庆 |
| 战斗素材 | 三处区域背景、首批约 6 种敌人、角色战斗姿态与基础特效 |
| 结局插画 | 现有 11 种结局逐步补齐 |
| 界面素材 | 一套统一按钮、面板、菜单图标与状态图标 |

先制作完整样板，确认一致性后批量扩充。生成继续使用用户已指定的项目图像接口，保存提示词、模型、时间及参考图信息，密钥不进入前端和素材记录。

### 4.3 AI 抠图方案

候选方案为 BiRefNet 与 RMBG 系列，先核实具体模型版本、许可证、部署条件和资源占用，再用相同原图比较。尚未选定正式方案，不预设它们都允许当前发布用途。

流程：高分辨率原图 → AI 前景蒙版 → 透明边缘与背景染色处理 → 局部修补 → WebP 导出 → 实际场景验收。

验收必须覆盖头发、发带、白衬衣、手指、裙摆、白袜、鞋带和腰带。分别在白、黑、蓝灰底及游戏场景中检查，不得有明显白边、缺失肢体、透明孔洞或残留地面。保留原图、蒙版和修补版本，生成结果可重复处理。

## 5. 服装购买与展示

核心闭环：赚取金币 → 商店看款与购买 → 衣橱穿着 → 主界面即时展示 → 剧情适时回应。

- 参考《美少女梦工场2》的安排，但原版准确服装清单、季节规则和属性效果须另行核对，不把记忆中的细节当成已确认设定。
- 款式覆盖日常、夏季、冬季、正式场合等；后续增加节庆与特殊奖励服装。
- 不同款式改变轮廓、领口、袖型、裙长、鞋子或配饰，保持相应年龄的比例。
- 衣服记录价格、适用年龄、获取方式和用途。购买后持久保存，重复购买有明确限制。
- 年龄变化时自动切换到适配的默认衣装；旧衣保留收藏，不出现不合体素材。跨年龄是否共用购买资格，在样板中确定并写明。
- 季节和服装效果作为可配置规则，先保证购买与展示闭环，再平衡属性影响。
- 上课、打工与战斗使用对应活动服装或装备画面，避免要求玩家每次手动换装；日常主界面恢复玩家选择的穿着。
- 获得新衣、首次穿礼服等可以触发专属谈心或事件。

## 6. 主线与事件系统

### 6.1 成长主线

规划 8 个年度章节，覆盖 10–17 岁，18 岁进行成长收束与结局。下面是章节主题草案，具体人物与事件在剧本阶段确定。

| 年龄 | 章节主题 | 主要作用 |
|---|---|---|
| 10 岁 | 新的家 | 建立家庭关系，认识城镇与基础生活 |
| 11 岁 | 第一个愿望 | 接触兴趣、朋友与第一次小目标 |
| 12 岁 | 与别人不同 | 引入竞争、比较和选择的代价 |
| 13 岁 | 第一次挫折 | 面对失败，形成亲子沟通差异 |
| 14 岁 | 自己的决定 | 兴趣与家庭期待产生分歧 |
| 15 岁 | 责任与信任 | 把工作、伙伴和探索经历带回主线 |
| 16 岁 | 未来的方向 | 不同培养路线出现对应剧情回应 |
| 17 岁 | 迈向明天 | 收回伏笔，选择未来，准备成年告别 |

主线保留共同节点，同时根据培养方向、关系和历史选择提供分支；不能仅由最终属性决定全部剧情。低属性或错过支线也能完成成长，不因单次选错永久卡住主线。

### 6.2 首轮事件规模

以至少 80 个独立可触发事件为首轮目标，现有 20 个事件逐条审阅后决定保留、改写或替换，不直接累加。仅换一句台词的变体不计为新事件。

| 分类 | 目标数量 |
|---|---:|
| 主线节点（每年约 3 个） | 24 |
| 角色支线（约 4 条，每条 5 个节点） | 20 |
| 家庭、课程、工作与服装事件 | 20 |
| 季节节庆、探索与特殊遭遇 | 16 |
| 合计 | 80 |

这些是全局内容库数量，并非单周目必定触发数量。互斥分支和不同路线鼓励重复游玩；重要主线节点保持可达。

### 6.3 触发与写作规则

- 条件支持年龄、月份、季节、地点、属性、压力、亲密度、活动次数、服装、人物关系和剧情标记。
- 区分必达主线、条件支线、节庆事件与随机日常，设置优先级、队列、冷却和单次结算上限。
- 主线条件未满足时提供合理的延迟、替代入口或保底节点；冲突事件不得静默丢失。
- 每个事件有唯一编号、前置、选项、结果、数值效果、后续标记与美术音频引用。
- 选择体现实际取舍，并在后续对话、关系或情节中回应；避免选项不同但结果完全相同。
- 普通事件控制篇幅，关键剧情允许多段对话；提供逐句显示、立即显示和跳过已读。
- 重要人物有清晰动机与连续发展，围绕家庭、友情、兴趣和成长组织故事。
- 手账记录关键经历与选择；跨周目收藏与当前周目剧情标记分开保存。

## 7. 音效与音乐

### 7.1 CC0 音效

优先从提供明确授权标识的素材库查找，如 Kenney、OpenGameArt、Freesound；逐个文件核实 CC0，不能仅凭网站名称判断。记录素材名、作者、来源页、下载时间、许可证与处理方式。

首批覆盖确认/返回、翻页、金币支出与获得、购买、换装、日程完成、事件提示、攻击、命中、受伤、胜利和失败。统一响度、裁掉多余静音、控制连续播放，提供音乐和音效独立音量、静音与设置保存。手机浏览器首次交互后启用音频，切后台暂停。

### 7.2 AI 音乐交付要求

交付完整场景需求表和可直接使用的提示词。首批规划 7 首背景音乐，约 60–120 秒，纯器乐，可自然循环；另配短胜利与结局提示旋律。实际生成工具和音频成品不视为已完成，选定工具后再验证授权、循环和音质。

共同提示词：

> 原创器乐游戏配乐，明亮清新的幻想女儿养成游戏，带有 1990 年代日式模拟养成游戏的温暖气息。小型室内乐，旋律清楚、编曲克制，适合长时间聆听。无人声、无环境音、无突然音量变化，不引用已有作品旋律。约 90 秒，可无缝循环，首尾速度、节拍、和声与混响尾音自然衔接。

在共同提示词后追加各场景要求：

| 曲目 | 场景与追加提示词 |
|---|---|
| 家园日常 | 安心、亲切、轻快；长笛、单簧管、拨弦弦乐、柔和钢琴；约 90 BPM，无强烈鼓点 |
| 城镇生活 | 晨间小镇、人情味、轻微好奇；木管、原声吉他、轻打击乐；约 105 BPM |
| 夜晚谈心 | 安静、信任、温柔；钢琴、竖琴、少量长音弦乐；约 65 BPM，避免悲伤过重 |
| 野外探索 | 自然、未知、适度神秘；木管、拨弦与轻柔打击乐；约 95 BPM，不做恐怖氛围 |
| 战斗 | 有行动感和紧迫感，仍符合清新幻想世界；短弓弦乐、木管、定音鼓；约 135 BPM，避免重金属和史诗合唱 |
| 节庆 | 欢快、热闹、有仪式感；木管、手鼓、拨弦、适量铜管；约 115 BPM，不喧闹刺耳 |
| 成长与告别 | 温柔、感动、希望与轻微不舍；钢琴、大提琴、长笛；约 75 BPM，情绪缓慢展开 |

“可循环”需要实际剪辑与连续播放验收，不能只依赖提示词声明。各曲目尽量复用原创主题动机，形成统一听感。

## 8. 技术实施与存档

沿用现有 TypeScript 养成规则与 Phaser 场景显示，不为界面改造重写全部游戏逻辑。剧情、衣装与素材按数据驱动组织，表现层读取状态，避免把条件散落在界面代码里。

- 事件增加条件评估、优先级调度、队列、历史、冷却和支线进度。
- 衣装增加款式、年龄版本、所有权、当前穿着、获取方式与可选效果。
- 素材清单统一登记背景、人物、表情、服装、事件插画、敌人与声音，检查引用是否存在。
- 高分辨率源图与移动端素材分开；按当前场景预加载，避免一次下载全部图片。
- 新存档加版本号与迁移，保留现有进度、金币和收藏；旧三色服装明确映射，导入失败不得覆盖原存档。
- 构建与玩法测试继续沿用现有脚本；新增测试重点覆盖剧情可达性、触发冲突、换装购买与存档迁移。

## 9. 分阶段交付

按里程碑推进，不在素材和剧本清单未确定时承诺日历工期。每阶段交付可试玩版本及完成清单；需审美确认的节点同时提供实际画面。

| 阶段 | 工作与交付 | 完成标准 |
|---|---|---|
| M0：规格准备 | 核对原作换装安排；界面结构图；主线大纲；事件和素材台账；抠图对比 | 数据字段、素材编号、首批内容与验收口径明确 |
| M1：完整样板 | 新版主界面；两个年龄段各两套不同款式；购买与换装；一个图文剧情事件；一场有配图和音效的战斗 | 手机端可实际操作，画风、分层、抠图和声音能整体评审 |
| M2：10–11 岁内容 | 两年主线、首批支线与日常事件，目标约 20 个事件；触发调度；对应场景与插画 | 两年可连续游玩，主线无死锁，选择有后续回应 |
| M3：八年内容扩展 | 8 个年度章节、至少 80 个事件；三个年龄阶段；服装、活动、探索与结局素材 | 全年龄流程可达，各主要培养路线都有剧情反馈 |
| M4：体验与发布候选 | CC0 音效整合；音乐需求与提示词定稿；有成品时完成音乐接入；性能、存档与平衡优化 | 完整成长、素材加载、声音开关和兼容性检查通过，已知问题公开记录 |

M1 的两个年龄段用于快速验证成长与换装方案；第三个年龄阶段在后续扩展。M1 确认后再批量生产相同规格素材，减少返工。

## 10. 验收与完成定义

1. 界面：主界面第一眼呈现人物和游戏场景；高频操作集中，整体不再由通用网页卡片构成。
2. 美术：画风与获批基准一致，重要玩法均有对应画面；服装具有真实款式差异，年龄和轮廓正确。
3. 抠图：多底色与实际背景检查通过，头发、白衣、腿部、配饰完整，无明显残留背景。
4. 换装：购买扣款、所有权、穿着、年龄切换和存档恢复一致，不重复扣费或丢失已购衣服。
5. 剧情：至少 80 个独立事件经内容校验；主线可完成，分支条件可达，事件不会无限重复或阻塞流程。
6. 事件节奏：日程推进不被大量弹窗打断；玩家可以快速显示文字、查看历史和理解结果。
7. 声音：使用的外部音效有可核验 CC0 记录，无明显爆音、音量突变或重复叠播；音乐提示词与成品状态分开登记。
8. 稳定性：构建、规则测试、关键路线模拟和浏览器冒烟通过；覆盖手机宽度、触控、后台恢复与存档迁移。

## 11. 配套文档与范围边界

实施时补齐：本作剧情写作规范、主线章节表、事件台账、角色关系表、服装目录、美术素材清单、抠图评测记录、CC0 音效来源表、音乐需求与提示词、版本验收记录。

本轮先完成游戏内容和表现升级；联网账号、云存档、付费商城、配音、复杂骨骼动画与新平台发布不列入当前必交范围。AI 绘图调用费用、素材工作量与性能问题以实际记录评估，发现范围变化时更新本计划。
