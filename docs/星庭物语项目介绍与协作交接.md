# 星庭物语：项目介绍与智能体协作交接

> 更新：2026-11-04。供策划、程序、美术、音频和测试智能体接手使用。本文依据代码与历史文档整理；历史验证不代表本次重新运行。接手前请核对最新用户要求、工作区状态和相关实现。

## 1. 项目定位

《星庭物语》是原创竖屏手机女儿养成游戏。玩家作为养育者，从女儿 10 岁起安排课程、工作、休息和探索，陪伴她成长到 18 岁；完整一局 96 个月。能力、心情、亲密、人际关系及选择共同影响成长故事和结局。

本作以日程安排和角色成长为核心，人物、剧情、美术和游戏规则均采用原创设计。整体风格明亮、干净、清新，具有经典日式养成游戏质感，适合手机长期阅读和操作。

当前是**可完整游玩的网页 Alpha**，并非正式发布版。仍需试玩、剧情和数值精修、美术统一、真机验证及正式音乐、配音等工作。

## 2. 用户已明确的要求

- 手机竖屏优先，字号与触控区域足够大，不为塞满屏幕牺牲可读性。
- 主界面以女儿与场景为中心。用户提供的主界面图片**只参考布局，不参考画风**；人物、房间和家具比例应合理。
- 界面要有经典游戏的场景与面板质感，避免方正应用窗口及大量通用网页卡片；高频入口清楚、稳定。
- 日程确认按钮必须容易看到；月份完成后逐项呈现活动结果并配合动态演出，不能只有简陋列表。
- 活动、事件、战斗和结局应有合适画面。普通事件可合理复用背景和立绘，不用无关插画机械填充。
- 换装要有不同款式和年龄适配，购买与穿着分开；同款换色不能算作多个新款式。
- 有贯穿成长的主线和大量触发事件。女儿应有自己的想法，早期选择在后续获得恰当回应。
- 美术以用户认可的 `cel-v3` 赛璐璐测试图为基准，不回退到水彩、厚涂、昏暗或现代亮面动漫风。
- 音效记录许可来源；音乐明确需求和试听状态；女儿不同年龄采用固定音色，情绪效果需实际试听。

## 3. 当前玩法与剧情

每月有上旬、中旬、下旬三个日程槽，共 18 种课程、打工、休息与探索活动。能力为体力、智力、魅力、气质、武艺、品德，另有金币、压力、亲密度。还包括谈心、送礼、商店、服装、生日、收获祭与成长手账。

当前目录记录 80 个独立事件、160 个选项：24 个年度主线节点、20 个人物支线、16 个条件日常及 20 个早期生活事件。主线围绕新家、星庭手账、年度展览和未来选择；人物支线包括米拉、罗恩、诺拉和菲恩。每月最多产生一个待回应事件，到期主线优先；普通事件不保证单周目全部触发。条件可涉及年龄、季节、属性、压力、亲密、活动次数、服装和剧情标记。

探索包括森林、遗迹与山路三个区域，具有自动交锋、战斗回放和撤退等机制；有 11 种职业结局及跨周目收藏。实际规则和数量以 `src/raising/` 与 `docs/stargarden/剧情与事件目录.md` 为准。

月度结算已改为逐项演出：活动插画、运镜和状态变化依次展示，支持倍速、逐项推进、跳过及最终总结。当前动态主要是插画运镜和界面动效，并非完整逐帧角色动画。演出读取已结算结果，不能重复结算或发放奖励。

## 4. 换装与年龄

立绘分为 10—13、14—15、16—18 岁三个阶段。庭院来信是默认衣装；蔷薇午后、晴空序曲是同版型配色。晴日水手裙、林间冬日、花灯舞会为不同款式，各年龄有适配立绘。款式购买一次后跨年龄继续拥有；购买不会强制立即穿上。

房间、角色、服装和 UI 独立组合；部分默认服装使用配色叠层，新款使用对应年龄的整套透明立绘。表情使用独立头像，不是全身立绘实时换脸。当前没有完全自由组合身体、发型和每件衣服的系统。服装主要影响外观及部分事件条件，不要把温度惩罚或服装属性写成已实现。详见 `docs/stargarden/服装目录.md` 和 `src/raising/art.ts`。

## 5. 架构与目录

- 入口：`index.html` → `src/main.ts` → `startRaisingGame`；新游戏位于 `src/raising/`。
- 技术栈：TypeScript、Vite、Phaser 4。界面以 DOM/CSS 为主，Phaser 负责角色舞台和图片图层，目标 30 FPS；Web Audio 负责音效及占位旋律。
- `game.ts`：养成规则、月度推进、状态和结局；`adventure.ts`：探索战斗。逻辑尽量保持可测试、可复现；随机数复用 `src/core/rng.ts`。
- `content.ts`：活动、物品、结局和早期事件；`story.ts`：主线、支线、触发条件和剧情；`types.ts`：数据契约。
- `app.ts`：交互和页面；`stage.ts`：角色舞台；`art.ts`：素材、年龄和服装映射；`sound.ts`：游戏音效。
- `style.css`、`storybook.css`、`classic.css`、`home-layout.css` 均可能影响界面。调整前应检查加载和覆盖关系，尤其是窄屏、弹窗和底部固定区。
- `storage.ts` 和 `game.ts` 管理存档校验、读写及迁移。主要键为 `stargarden_save_v1`、`stargarden_meta_v1`，音效设置为 `stargarden_sound_v1`。修改需保留旧存档、服装所有权与跨周目收藏。
- `art-src/stargarden/` 保存素材源文件；`public/assets/stargarden/` 保存运行素材；`scripts/stargarden-*` 包含生成、处理、模拟和验收脚本；`tests/` 包含测试。

仓库保留原《问道长生》的 `src/core/`、`src/data/`、`src/render/` 及平台打包骨架。`docs/技术底层总结.md` 主要总结旧项目技术经验，不能据此断言本游戏已完成安卓或微信适配。`README.md` 同时包含两个项目的说明，执行命令前先核对入口；本作当前以手机网页为准。

## 6. 美术与资源

获批风格基准：`art-src/stargarden/style-tests/cel-v3.png`。方向是 1990 年代日式养成游戏的清新赛璐璐手绘感：细棕色轮廓、平涂、每种材质一层清晰硬边阴影、克制高光。避免水彩颗粒、厚重渐变、喷枪、泛黄、3D 和过大的通用萌系眼睛。

角色识别：栗棕色齐肩微卷发、碎刘海、琥珀棕眼睛和深灰绿发带；各年龄应像同一个人自然长大。新衣装、成长立绘、活动、事件、战斗、表情和结局原图在 `art-src/stargarden/production-v1/`，运行文件在 `public/assets/stargarden/production-v1/`。生成记录和提示词见 `art-src/generation_log.jsonl` 及对应素材目录。用户指定使用项目已有绘图接口，使用前先检查脚本和授权，不输出密钥。

新透明素材采用本地 BiRefNet ONNX，保留原图、蒙版及处理信息。需在深浅背景检查头发、白衣、手指、腿部、配饰、边缘和残留背景；自动抠图成功不等于视觉验收通过。详见 `docs/星庭物语美术规范.md` 与 `docs/stargarden/抠图与音效方案.md`。

## 7. 音效、音乐与配音

游戏已接入 Kenney CC0 界面和战斗音效，来源、映射及许可证见 `public/assets/stargarden/audio/sources.json` 和同目录记录。当前背景音乐仍是程序合成占位旋律。`public/assets/stargarden/audio/music-tests/home-bright-v1.mp3` 是约 30 秒 AI 试听，不代表七首正式音乐已制作或接入。场景需求和提示词见 `docs/stargarden/AI音乐需求与提示词.md`。

女儿配音已有音色与情绪试听，**尚未接入游戏剧情**：

| 年龄 | 音色 | 当前状态 |
| --- | --- | --- |
| 10—13 岁 | 已设计 `S_jPukgGbk2` | 强场景及表演提示的情绪测试获得用户认可。 |
| 14—15 岁 | 已设计 `S_yknZmKn32` | 已有情绪试听；与童年音色的连续性仍需比较确认。 |
| 16—18 岁 | 官方候选 `zh_female_roumeinvyou_uranus_bigtts` | 用户指定；已有官方 TTS 原声、旧版及明确 17 岁提示的对照，最终听感待确认。 |

此前两个已购槽位的状态记录各显示剩余 14 次设计，实际余额应重新查询。不得为了测试情绪重新设计或覆盖已用槽位。`seed-audio-1.0` 通过同一 `references.speaker` 加处境和表演提示生成语音。第一轮情绪不明显，明确场景、笑意、哭腔和节奏后用户表示可以；这仍是自然语言提示，而非保证稳定的结构化情绪参数，成品需逐条试听。

16—18 岁旧试听的页面标题写了年龄，但生成提示没有实际年龄要求；修正版明确 17 岁及自然音区。开发服务器启动后，三个年龄对比页为 `/assets/stargarden/audio/voice-age-comparison-v1/index.html`；成年候选对照页为 `/assets/stargarden/audio/voice-grown-diagnosis-v1/index.html`。详见 `docs/stargarden/正式音色设计与情绪测试.md`。

## 8. 启动与验证

当前项目位于 `D:\美少女养成`；目录若再变化，以包含本文件、`package.json` 和 `src/raising/` 的项目根目录为准。依赖已安装时：

```powershell
npm run dev -- --host 0.0.0.0 --port 5174 --strictPort
npm run build
npm run test:raising
npm run sim:raising -- 300
npm run smoke:raising
npm run smoke:raising:content
npm run smoke:raising:schedule
```

开发地址以 Vite 实际输出为准；端口被占用时换端口，不结束用户其他进程。手机与电脑在同一网络时可打开 Vite 输出的 Network 地址。浏览器冒烟脚本需先启动服务，具体配置以脚本为准。`npm run catalog:raising` 会更新生成的剧情和服装目录，运行前注意它会写文件。

2026-11-01 的开发记录报告过构建、规则测试、内容检查、定向模拟及多屏宽浏览器检查；这些属于历史结果，本次交接没有重新运行。历史模拟覆盖 11 种结局，但为目标导向模拟，不代表自然玩家结局分布。浏览器手机尺寸检查不等于真实手机长期试玩。

## 9. 后续工作与协作

1. 根据用户试玩反馈改善主界面、场景比例、手机字号和交互，保持底部操作清晰。
2. 精修剧情节奏、角色差异、选项后果、触发可达性及跨年回应；新增内容保持事件唯一、可达和存档兼容。
3. 统一人物年龄、服装与场景画风，补充适合活动、事件、战斗及结局的画面，人工检查透明边缘和移动端性能。
4. 用户确认各年龄音色与一致性后建立台词、情绪和音量台账，再制作并接入；正式音乐需试听、循环和响度验收。
5. 真机检查触摸、安全区、滚动、后台恢复、音频、存档、资源加载和长时间运行；结合真实试玩调整数值。
6. 安卓、微信、联网账号及正式发布属于后续范围，不能把旧骨架命令当成本游戏已通过平台验收。

多人或多智能体协作时，先阅读对应模块、相关文档及工作区状态，明确各自修改范围，避免覆盖其他人改动。不要随意重置工作区、覆盖存档、删除素材或重新设计音色。可能产生外部费用或消耗次数时先核对已有授权和成本。区分已实现、仅试听、历史验证和待确认；完成后说明修改文件、行为、未完成项及实际测试结果。

生成资源应保留来源、原图、提示词、模型、许可及处理记录。保护 API Key 和本地凭据，不复制到文档、聊天、日志、网页、截图或版本库；对外分享或提交前检查 Git 状态和忽略规则。修改存档、日程结算或剧情调度时验证迁移、重复结算与可达性；修改界面时检查多个手机宽度、文字遮挡和关键操作可见性。
