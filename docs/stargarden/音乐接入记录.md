## 处理流程

`python scripts/stargarden-music-build.py`（或 `npm run music:raising`）：

1. 读取选曲清单 `art-src/stargarden/audio/music-selection.json`（每个曲目选用哪个候选）。
2. 背景音乐：响度标准化到 −20 LUFS、真峰值 −2 dBTP，编码为 MP3 128 kbps 恒定码率（`.mp3`）。
3. 短乐句：在目标时长范围内找能量最低的 100 毫秒处剪断，末尾淡出，响度 −16 LUFS。目标范围：胜利 / 撤退 / 章节 3–5 秒，月末 2.5–4 秒，来信 2–4 秒，生日 / 收获祭 5–7 秒，结局 7–10 秒。
4. 输出到 `public/assets/stargarden/audio/music/<曲目>.mp3`，并在同目录 `manifest.json` 记录来源、剪切位置和实测响度。

当前产物：13 首背景音乐各 1.6–3.3 MB，8 段短乐句各 40–130 KB，合计约 36 MB；进入对应场景时才加载。

**短乐句是自动剪的**，剪断位置只保证落在较安静处，不保证乐句完整。务必在试听页确认，不满意时可以手动调整脚本里的范围，或请执行方交付真正的短乐句。

## 换选曲

1. `npm run dev` 后打开 `/art-src/stargarden/audio/music-review/index.html`（仅开发环境，不会打包进游戏）。
2. 逐个试听候选（短乐句播放的是剪辑后的版本），选好后点“下载选曲清单”。
3. 用下载的文件替换 `art-src/stargarden/audio/music-selection.json`，运行 `npm run music:raising`。

试听用的剪辑文件由 `python scripts/stargarden-music-build.py --preview` 生成到 `art-src/stargarden/audio/music-review/`（已加入 `.gitignore`）。

## 游戏内的播放规则（`src/raising/music.ts`）

| 场景 | 曲目 |
|---|---|
| 开场第 1–4 幕 / 第 5 幕 / 章节卡 | `bgm_opening_night` / `bgm_opening_morning` / `jingle_chapter` |
| 庭院、衣橱、手账 | `bgm_home`；冬季（12–2 月）用 `bgm_home_winter` |
| 城镇、日程页 | `bgm_town` |
| 最后一年（剩余 12 个月以内）与结局后 | `bgm_growing` |
| 日程逐项演出 | `bgm_schedule`；探索那一旬 `bgm_explore`；交锋 `bgm_battle`，结果 `jingle_victory` / `jingle_retreat` |
| 生日 / 收获祭（演出中） | `bgm_festival` + `jingle_birthday` / `jingle_festival_award` |
| 月度总结出现 | `jingle_month_end` |
| 剧情事件 | `bgm_story`；事件表情为难过的用 `bgm_rain`；出现时 `jingle_letter` |
| 谈心 | `bgm_night` |
| 结局揭晓 | `bgm_growing` + `jingle_ending` |

- 换曲交叉淡入淡出 0.9 秒；同一首不会因界面刷新而重播。
- 每首在结尾前 2.5 秒从头淡入下一遍，循环不留空隙。
- 短乐句播放时背景音乐压低到 35%，结束后恢复。
- 用 Web Audio 控制音量，iOS 上设置里的音量滑杆同样有效；切到后台时暂停。
- 新玩家默认开启音乐；浏览器要求先有一次点击，所以在第一次点屏幕时开始播放。设置里关闭后会记住。
- 设置存于 `stargarden_music_v1`，格式 `{ v: 2, enabled, volume }`。旧版（合成占位旋律时期，默认关闭）存下的“关”不作数，只保留音量；否则调过音量滑杆的老玩家会一直听不到音乐（2026-11-05 修复）。
- 原来的程序合成占位旋律已移除。

## 测试

`npm run smoke:raising:music`：首次点击后开始播放、庭院 / 城镇 / 谈心 / 冬季 / 最后一年的曲目、无缝循环交叠、短乐句压低与恢复、关闭后静音并记住设置。

## 2026-11-05 修复：触摸点击后没有音乐

原来在 `pointerdown` 时启动音乐。浏览器规定触摸屏上的 `pointerdown` 不算用户允许播放（要等手指抬起），所以手机、触摸屏和开发者工具的手机模拟下播放被拦截，且不会重试；鼠标点击则正常，无头测试的自动播放规则又更宽松，因此测试没发现。

现改为在 `click`、`touchend`、`keydown` 时启动，并且每次用户点击都会重试被拦下的播放（`MusicPlayer.unlock()`）。`smoke:raising:music` 改用 `--autoplay-policy=user-gesture-required` 与触摸点击测试。

## 2026-11-05 改用 MP3 与流式播放说明

- 用户在 VS Code 内置预览中能听到点击音效（OGG），却听不到音乐。原因是该环境的解码器不含 AAC（也不含 H.264，开场视频在那里只显示封面）。改为 MP3（128 kbps）后所有浏览器都能播放；体积由约 28 MB 增至约 36 MB。
- **流式播放**：背景音乐与短乐句都用音频元素边下载边播放，只缓冲正在播放的部分，不用 `decodeAudioData` 把整首解码进内存（3 分钟立体声整首解码约 60 MB）。同一时间最多两个音频在播放（换曲或循环交接的 1–2 秒），淡出后立即释放。只有几百毫秒的点击类音效才整段解码缓存。
