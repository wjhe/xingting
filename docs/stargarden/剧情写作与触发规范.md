# 剧情写作与触发规范

适用《星庭物语》，不沿用旧修仙骨架的事件字段。实际类型为 `src/raising/types.ts` 的 `StoryEvent`，当前主线与支线在 `src/raising/story.ts`，早期生活事件在 `content.ts`。

## 叙事原则

女儿有自己的想法，家长通过陪伴、安排与回应影响成长。故事围绕家、兴趣、朋友、挫折、责任和未来展开；不把女儿写成只会感谢玩家的数值奖励器。

主线以「星庭手账与年度成长展览」贯穿八年。同一件旧物、愿望或约定可以再次出现，但重逢时必须体现年龄和经历变化。重要选择留下标记，后续通过实际台词回忆，避免只有最后一刻才读取属性。

文案用自然中文，人物说话各有习惯。普通事件有具体生活细节与小冲突，主线节点有情绪推进。两项选择可以分别侧重安慰、讨论、实践、独立或协作，不把其中一项写成明显恶意来制造假选择。

## 数据与标记

事件必须有唯一编号、标题、正文、图标和至少两个选择。每个选择包含明确结果文本，效果必须与文案一致。当前 `Outcome` 支持能力、金币、压力、亲密和一个剧情标记；新增复杂效果时先扩展类型与校验。

- 主线：`main_年度序号_节点序号`，每年约三节点，`dueMonth` 取实际已完成月份。
- 人物支线：`side_人物_节点`，前置为前一节点的 `event:编号`，并检查课程或工作次数。
- 条件日常：`daily_主题`，可限制季节、压力、亲密度和当前衣装。
- 完成标记由引擎写入 `event:编号`；选项标记用于记住选择，不复用为不同含义。
- 同一个事件当前只发生一次。可重复台词不计为新的独立事件数量。

## 条件与调度

`conditions` 支持月份、最低属性、压力上下限、最低亲密、活动累计次数、前置与排除标记、当前服装。月份为 1–12；年龄由游戏月份推算。`minAge`、`maxAge` 独立限制年龄。

月结算后先从符合条件的未读事件中选择到期主线，按到期月份排序。没有主线时从条件支线与生活事件中抽取；支线有较高机会，但不是每次都抢占日常。每个月最多一个待回应事件，回应后才继续安排日程。

未抽到的常规条件事件保留在候选库；月份事件在后续符合季节时重新进入候选池。它们没有被永久完成，也不是每个周目都必须出现。当前没有同月连续弹出的事件队列。

主线不依赖高属性门槛，低属性和休息路线也能完成。旧存档升级时记录 `storyStartMonth`，从当前时间接入新主线，不要求高龄角色补读十岁时的新剧情。旧日程次数没有可靠来源时不凭空重建，新增活动计数从升级后记录。

## 配图与验收

关键节点用专属插画，普通节点可以用独立背景与当前人物合成。画面必须符合当前事件的年龄与情绪；不能拿任意战斗图填满生活剧情。图片路径集中登记，生成日志保留完整提示词。

写完运行 `npm run test:raising` 和 `npm run catalog:raising`。校验编号唯一、前置存在、至少一个免费出口、事件不会重复、各主线能在成年前到达。测试通过后仍需人工读文案、检查选择与数值是否一致，并试玩触发节奏。
