# 《问道长生》广告变现方案

> 2026-10-26 初稿。按开发计划，广告在 M4（平台接入）阶段和微信、APK 一起接入；框架和网页版的假广告可以提前做。

## 一、总体思路

**以激励视频为主，插屏只在转世这种天然的停顿处偶尔出现，不放横幅。**

- 这是文字游戏，玩家要静下心来读。读到一半弹广告最伤体验，留存掉了，广告收入也跟着掉。
- 激励视频由玩家主动选择，正好契合"寿元有限、选择有代价"的核心设计：花 30 秒，换一次转机。

## 二、广告位

### 激励视频

| 优先级 | 编号 | 时机 | 看完得到什么 | 次数限制 |
|---|---|---|---|---|
| ★★★ | `revive` | 战死或渡天劫被劈死时 | 「残魂不灭」：保住性命，按重伤处理（修为减半、折寿） | 每世 1 次 |
| ★★★ | `undo_break` | 突破失败、走火入魔后 | 「逆天改命」：找回这次损失的境界和修为（**寿元不退**，见附录） | 每次突破 1 次，每天 5 次 |
| ★★ | `rebirth_points` | 转世结算时 | 本世轮回点 ×1.5 | 每天 3 次 |
| ★★ | `talent_reroll` | 开局抽天赋时 | 多刷新一次天赋 | 每世 1 次 |
| ★★ | `save_herbs` | 丹房炸炉后 | 保住这一炉药材 | 每天 5 次 |
| ★ | `shop_refresh` | 坊市 | 立即刷新今年的货架 | 每个游戏年 1 次，每天 5 次 |
| ★ | `offline_double` | 回到游戏、有离线灵气储备时 | 灵气储备 ×2 | 每天 2 次 |

前两个价值最高：在玩家最痛的时候给一个转机，转化率最好，应该最先做。

按钮文案要说清楚"看一段视频，换什么"，例如：「观看视频 · 残魂不灭（本世仅一次）」。旁边永远保留不看广告的选项，例如「就此轮回」。

### 插屏广告

- 只在**转世结算页**出现。
- 两次之间至少间隔 3 分钟，每天最多 5 次。
- **第一世完全不出**，新玩家前 30 分钟一律不出。
- 玩家当天看过激励视频的，插屏频率再减半。看过广告的人已经贡献了收入，不要再打扰。

### 刻意不做的

- **不能直接买寿元，也不能跳过天劫或心魔关。** 寿元是游戏最核心的张力，能用广告买，游戏就没意思了。
- **不放横幅广告。** 会破坏水墨界面，收益也低。
- **不做开屏广告。**
- **事件阅读、战斗演出、全屏转场期间，任何广告都不弹。**

## 三、数值原则

- 现在的数值和模拟数据都按"不看广告"调的。广告收益应该是锦上添花，大约让人快 10%～20%、少一些挫败感。
- **不看广告也能完整通关、拿到所有结局。** 否则玩家会骂"逼氪"，审核也可能有风险。
- 上线前，在模拟脚本里加一个"每次都看广告"的玩家策略，确认各境界到达率不会翻倍。

## 四、技术方案

代码里已经预留了平台层（`src/platform`），游戏逻辑不直接调用平台 API。

1. **统一接口**：平台层加一个"播放激励视频"的方法，传入广告位编号，返回玩家是否完整看完。再加一个"展示插屏"的方法。
2. **各平台实现**：
   - **网页版（开发测试用）**：弹出一个假广告，倒数 2 秒就算看完，也能手动"中途关闭"，用来测试两种结果。
   - **微信小游戏**：用微信自带的激励视频和插屏广告组件，需要先开通"流量主"，并在后台创建广告位。
   - **安卓 APK**：国内一般接穿山甲（字节）或优量汇（腾讯）的广告 SDK，需要写一个 Capacitor 原生插件，工作量比微信大。
3. **次数限制**：每个广告位的"今日已用次数"和"本世已用次数"记在轮回存档里，按自然日重置。界面上显示剩余次数。
4. **失败处理**：广告加载失败或没有广告可放时，按钮显示「暂无可用视频」并置灰，不能卡住游戏流程。
5. **奖励发放**：只有看完才发奖励。中途关闭的，提示"视频未看完，未获得奖励"。

## 五、上线前要确认的事

| 事项 | 说明 |
|---|---|
| 版号 | 纯广告变现、没有内购的小游戏是否需要版号、需要哪些资质，近几年政策有变化。上线前以微信官方和主管部门的最新规则为准 |
| 流量主门槛 | 微信开通流量主有用户量等门槛，新游戏刚上线时可能暂时开不了，要预留这段时间 |
| 隐私协议 | 安卓上架必须提供隐私协议，写明接入的广告 SDK 会收集哪些信息；首次启动时要先征得用户同意，再初始化 SDK |
| 未成年人保护 | 按平台要求处理防沉迷与实名认证 |
| 广告内容 | 在广告后台屏蔽与游戏调性冲突的类目（如博彩擦边、低俗内容） |

## 六、上线后看的数据

- **各广告位的展示率、观看完成率**：完成率低，说明奖励不够吸引，或者出现的时机不对。
- **人均每天看广告次数**、**广告收入**。
- **次日留存、7 日留存**：要和没接广告时的数据对比。留存明显下降，就要减少插屏，或者降低广告出现的频率。
- **转世结算页的流失率**：插屏是否把人赶走了。

## 七、实施顺序

1. 平台层接口和网页版假广告，再接上 `revive` 和 `undo_break` 两个广告位，跑通完整流程（可提前做）。
2. 其余激励视频广告位、次数限制、存档记录。
3. 模拟脚本加入"看广告"策略，复核数值。
4. M4：接入微信广告组件，真机测试。
5. M4：安卓接入广告 SDK，处理隐私协议。
6. 上线后观察数据，再决定插屏是否开启、开多少。

## 附：实现记录（2026-10-28）

第一、二、三步已完成，广告目前是模拟的（网页版和安卓 APK 弹一层假广告，倒数 2 秒算看完，可中途关闭）。微信端先按"暂无可用视频"处理。

**代码位置**
- 平台接口：`src/platform/types.ts` 的 `AdProvider`（`rewardedReady` / `showRewarded` / `showInterstitial`）。接真广告时只需各平台实现这三个方法。
- 假广告：`src/platform/fakeAds.ts`。开发时在浏览器控制台执行 `localStorage.setItem('wdcs_fake_ads', 'nofill')` 可模拟"暂无广告"。
- 次数与插屏规则：`src/core/ads.ts`，记在轮回存档里，按自然日清零。
- 奖励逻辑：`src/core/game.ts`（`revive`、`undoBreak`、`saveHerbs`、`adRefreshShop`、`addOfflineReserve`），挽回类奖励只在"刚发生、还没再做别的事"时有效。
- 界面：`src/render/ads.ts`（按钮文案、播放、记账、插屏），各场景按钮在 `MainScene`、`tabs.ts`、`RebirthScene`、`CreateScene`。
- 走查：`node scripts/ads-check.mjs`（需先 `npm run dev`）在浏览器里把所有广告位走一遍。

**数值复核**（`npm run sim -- 400 8 smart ads`，假设每次都看、日上限按每世计，偏宽松）

按方案原样（逆天改命连寿元一起找回），渡劫到达率第 1 世 3%→8%、第 8 世 6%→12%，翻倍了；逐个广告位测下来，几乎全部来自逆天改命：后期突破失败一次折几十年寿元，全额找回等于用广告买寿元。改为**只找回境界和修为、寿元不退**后见下表：首末两世变化不大，中间几世最多约 1.5 倍，不再翻倍。因此反噬折寿而死的，逆天改命也救不回。

| | 第 1 世：筑基 / 金丹 / 元婴 / 渡劫 | 第 8 世：筑基 / 金丹 / 元婴 / 渡劫 |
|---|---|---|
| 不看广告 | 80% / 24% / 9% / 3% | 86% / 32% / 15% / 6% |
| 每次都看 | 81% / 26% / 8% / 3% | 89% / 34% / 14% / 7% |

中间几世渡劫最多 5%→9%（第 5 世），约 1.5 倍；战死率从 2%～5% 降到 0%～1%（残魂不灭）。人均每世看 9.5 条，一世多花约 8 分钟。

**还没做的**
- 微信：开通流量主后接 `wx.createRewardedVideoAd` / `wx.createInterstitialAd`。
- 安卓：拿到广告 SDK 后写 Capacitor 原生插件替换假广告；隐私协议弹窗要在初始化 SDK 之前。
- 正式包里假广告必须换掉（现在 APK 也会弹"模拟激励视频"）。

## 附：接入 TapADN（2026-10-31）

广告平台选用 TapTap 的 **TapADN**（Dirichlet，https://ssp.dirichlet.cn/docs/ ），Android SDK 5.3.1.8（不含聚合版）。以后想同时拉穿山甲、优量汇的广告，可换成「TapADN SDK（聚合）」。

**需要你在 ssp.dirichlet.cn 后台完成**
1. 创建媒体（应用），记下**媒体 ID**、**媒体密钥**。
2. 创建广告位，都选**竖屏**：
   - 激励视频广告位（必需）
   - 插屏广告位（可选；不建就不放插屏）
3. 填写 `android-keys/tapad.properties`（不进版本库），然后 `npm run build:android`：
   ```
   mediaId=媒体 ID
   mediaName=问道长生
   mediaKey=媒体密钥
   rewardSpaceId=激励视频广告位 ID
   interstitialSpaceId=插屏广告位 ID
   ```

**实现要点**
- 原生插件：`android/app/src/main/java/com/wendao/changsheng/TapAdPlugin.java`；AAR 在 `android/app/libs/`（MD5 已与官网核对）。
- 只在玩家同意隐私政策后初始化（门口场景里调用 `initAppAds`）。
- 隐私开关按最小必要配置：只用 Android ID 和 OAID；位置、电话状态、Wi-Fi、MAC、传感器、应用列表都关闭；不开摇一摇。AAR 自带的 `QUERY_ALL_PACKAGES` 权限在 `AndroidManifest.xml` 里移除了。
- 激励视频：TapADN 回调 `onRewardVerify` 为真才算看完；加载超过 8 秒或失败按"暂无可用视频"处理。看完一条后在后台预加载下一条。
- 「角色 > 设置」里有「个性化广告」开关（TapADN 合规要求），只在真广告启用时显示。
- 隐私政策（`src/data/legal.ts`）已按 TapADN 的披露示例写入，并更新了协议版本，老玩家会被要求重新同意。
- 没有配置 `tapad.properties` 时：调试包继续用模拟广告，**正式包按"暂无可用视频"处理**，不会把模拟广告带上线。
- 激励视频的服务端校验（S2S）没有接：本游戏没有服务器，奖励在客户端发放。
- 广告的横竖屏完全由后台广告位配置决定（SDK 从返回的 `orientation` 字段选 `PortraitActivity` / `LandscapeActivity`），代码里没有可覆盖的参数。改完后台要**重启一次游戏**再看：看完一条会预加载下一条，旧的那条仍按旧方向展示，容易误以为没生效。（2026-10-31 实测：改成竖屏后新拉取的广告是 1080×2400 竖屏。）
