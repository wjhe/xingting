# 技术底层总结（给开发新游戏的 AI 看）

> 来源项目：《问道长生》，竖屏文字修仙游戏，一套代码发布到**浏览器 / 安卓 APK / 微信小游戏**。
> 本文只讲底层技术和工程做法，不讲修仙玩法。文中路径都相对于原项目根目录；"可直接复制"的文件拿过去基本不用改。
>
> **新游戏不一定是文字游戏。**下面每一节标了适用范围：
> - 【通用】任何类型的 Phaser 手机游戏都适用（动作、射击、消除、塔防、模拟经营……）
> - 【回合/菜单类】适用于"点一下、算一步、播一段"的游戏（文字冒险、卡牌、回合制、放置、经营菜单）
> - 【本项目】只是这个游戏的具体做法，供参考
>
> 实时类游戏（动作、射击、跑酷等）请重点看**第 12 节**，那里写了这套骨架要怎么改。

## 0. 一句话架构

```
src/core/      纯 TypeScript 游戏逻辑（不碰引擎、不碰平台、不读系统时钟）
src/data/      全部内容配置（JSON），注入给 core
src/render/    Phaser 4 场景与 UI，只调用 core 的公开方法，然后按 state 重画
src/platform/  平台能力接口 + 各平台实现（存储、屏幕、安全区、输入框、广告、登录）
```

依赖方向只允许 `render → core`、`render → platform`、`core → data 类型`。**core 里出现 `Phaser`、`window`、`localStorage`、`Date.now()` 都算违规。**这条规则让逻辑层可以在 Node 里跑单元测试、跑上千局的数值模拟，也让三个平台共用同一份逻辑。

## 2. 逻辑层（src/core）的写法

### 2.1 单一入口类 + 纯 JSON 状态

- `Game` 类是逻辑的**唯一入口**（`src/core/game.ts`）。界面只调用它的动作方法（`closedDoor()`、`explore()`、`choose(i)`、`buy(id)`…）和只读 getter，然后整页重画。
- 全部可存档状态放在一个**纯 JSON 对象** `GameState` 里（`src/core/types.ts`），`Game` 只持有它的引用。存档 = `JSON.stringify(state)`，读档 = `new Game(JSON.parse(raw), CONTENT)`。不要在 `Game` 的私有字段里放需要存档的东西。
- 内容配置（事件、物品、敌人…）通过构造函数注入：`new Game(state, CONTENT)`，构造时建 `Map` 索引。测试可以注入精简的假数据。

### 2.2 可存档的种子随机数

`src/core/rng.ts`（**可直接复制**）：mulberry32，整个状态就是一个 32 位整数。

- 状态存进 `state.rngState`；每个动作方法结束时 `sync()` 把 `rng.state` 写回。读档后随机序列接着走，"存档刷概率"无效。
- 提供 `next()` / `int(min,max)` / `chance(p)` / `pickWeighted(items, weightFn)`。
- 测试和模拟用固定种子即可复现任何一局。

### 2.3 时间由调用方传入

逻辑层**不读系统时钟**。需要真实时间的功能（离线收益、广告每日次数）一律把 `now: number` 当参数传进去：`game.syncClock(Date.now())`、`adsLeft(meta, slot, now)`。游戏内时间（月份、年龄）是状态里的普通数字。

### 2.4 日志驱动文字、信号驱动演出

> 范围：信号机制【通用】；日志【回合/菜单类】。实时游戏里"信号"就是逻辑层每一步产生的事件（命中、死亡、拾取、升级），界面据此播特效和音效，逻辑层仍然不知道特效的存在。

逻辑层产出两种东西给界面：

1. **日志** `state.log: { kind, text }[]`（上限 300 条，进存档）。`kind` 决定颜色和排版：`time`（时间分隔线）、`title`、`art`（插图 id）、`text`、`good`、`bad`、`system`、`battle`、`whisper`。界面只负责把日志渲染出来，**所有剧情文字都由逻辑层写**。
2. **信号** `Signal[]`（不进存档）：本次操作里发生的"值得演出的事"，例如 `{type:'door', months, gain}`、`{type:'battle', replay}`、`{type:'realm', ...}`、`{type:'death', ...}`。界面每次操作后调用 `game.drainSignals()` 取走，依次排进演出队列。

战斗是**全自动**的：逻辑层一次算完整场，输出 `BattleReplay`（双方初始数值 + 每回合 `steps`），界面按 replay 逐回合播动画，"点击跳过"只是跳到结局。这样逻辑和动画完全解耦，模拟器里跳过动画即可。

### 2.5 存档版本与兼容

- `SAVE_VERSION` 常量；版本不符时 `deserialize()` 返回 `null`，由调用方决定开新档。
- 加新字段时**一律可选**（`field?: T`），注释写"旧存档没有此字段"，读的地方用 `??` 给默认值，或在构造函数里 `state.x ??= 默认值`。这样不用升版本号，老玩家存档不丢。
- **两份存档分开**（`src/render/session.ts`）：
  - `wdcs_save_v1`：本局状态，死亡/重开时删除；
  - `wdcs_meta_v1`：跨局状态（轮回点、解锁、图鉴、广告账本），永不随局清空。
  - 另有 `wdcs_settings_v1`（设置）、隐私同意版本号。所有 key 带项目前缀和版本后缀。

### 2.6 数据驱动的事件系统

> 范围：具体结构【本项目】；"内容全部写成 JSON、逻辑层统一解释、测试校验引用"的思路【通用】——换成关卡、波次、敌人、技能、卡牌、配方表都一样。

事件全在 `src/data/events/*.json`，新文件必须在 `src/data/index.ts` 的 `EVENT_FILES` 里登记。核心结构（详见 `types.ts` 的 `EventDef`）：

```jsonc
{
  "id": "village_boar", "title": "野猪下山", "art": "village_boar",
  "region": ["qingshi_village"],     // 进入哪个区域的随机池；不填 = 只能被 next 串联
  "weight": 8, "once": false,
  "conditions": { "realm_min": "lianqi", "flags": [], "not_flags": [], "meta_flags": [], "has_items": [] },
  "text": "……",
  "options": [
    { "text": "抄起扁担上前", "battle": { "enemy": "wild_boar", "win": { "result": "…", "effects": [...] }, "lose": {...} } },
    { "text": "帮村民加固篱笆", "check": { "attr": "gengu", "dc": 8 }, "success": {...}, "fail": {...} },
    { "text": "离开", "requires": { "stones": 30 }, "effects": [...], "next": "另一个事件id" }
  ]
}
```

- `Effect` 是带 `type` 的联合类型（修为、物品、货币、属性、标记、跨局标记、结局…），逻辑层一个 `applyEffect` 统一处理。
- 检定 = `d10 + 属性 >= dc`；界面显示的"约 70%"由逻辑层精确计算，不是界面估的。
- 抽事件：按区域 + 条件过滤 → 按权重抽；最近抽过的事件权重 ×0.1，降低重复。
- 写作规范另有一份（原项目 `docs/事件写作规范.md`），给写内容的 AI 用。

### 2.7 自动玩家与数值模拟

- `src/core/bot.ts`：`botStep(game, rng, smart)` 每次做一个动作（选选项、闭关、历练、突破、买卖…）。`smart=false` 乱选，`smart=true` 会挑划算的选项、打不过不打。
- `scripts/simulate.ts`：`npm run sim -- 600 8` → 600 个玩家各连玩 8 局，统计每局到达的境界分布、按每类动作估的真实耗时（分钟）。**难度、广告收益、"几十分钟一轮回"这类设计目标都靠它校准**，不要凭感觉调数。
- 有了"逻辑层纯函数 + 可复现随机数"，这一层才做得出来。新游戏务必保留。

## 3. 渲染层（src/render）的写法

### 3.1 分辨率与坐标

`src/render/boot.ts` 的 `startGame()`：

- 画布按**物理像素**创建：`width = screenCssW * dpr`（dpr 封顶 3），保证文字清晰。
- 所有场景统一用 **750 宽的设计坐标**（`DESIGN_W = 750`），主相机 `setOrigin(0,0).setZoom(pw / 750)`。高度随屏幕变（`layout.height = ph / zoom`）。
- 安全区（刘海、微信胶囊按钮、底部横条）由平台层给 CSS 像素，换算成设计坐标存进 `layout.safeTop/safeBottom`。
- `platform` 和 `layout` 在 `preBoot` 回调里放进 `game.registry`，任何场景用 `getLayout(scene)` / `getPlatform(scene)` 取。
- 浏览器里 `Scale.FIT + CENTER_BOTH`，桌面宽屏时把宽度裁到 9:16 模拟手机；微信用 `Scale.NONE` + 传入的主画布。
- **`fps: { target: 30, limit: 30 }`**：文字游戏不需要 60 帧，限 30 帧省电不发烫。动画都按时间算，速度不受影响。**实时游戏改回 60**（或不设上限），见第 12 节。

### 3.2 场景流程

```
Boot（加载页，加载完不关闭，后台继续加载音频）
 └─ launch → Gate（隐私同意 → 平台登录/防沉迷；网页、微信直接放行）
      ├─ 有存档 → Main（主界面：状态栏 + 页签 + 行动区）
      └─ 无存档 → Create（建角）→ Main
Main 死亡/重开 → Rebirth（结算、跨局成长）→ Create
```

### 3.3 主界面的"动作 → 存档 → 重画 → 演出"循环

> 范围：【回合/菜单类】。实时游戏的主循环见第 12 节；但实时游戏里的菜单界面（背包、商店、升级、结算）照样可以用这个循环。

`MainScene.act(fn)` 是所有改变游戏状态的入口，顺序固定：

1. `before = snapshot()`（货币、物品数等），记下日志长度；
2. 执行 `fn()`（调用 `Game` 的某个动作方法）；
3. `after = snapshot()`，取出新增的日志条目；
4. **立即存档**（`saveGame(platform, game)`）——任何操作后都存，不怕杀进程；
5. `refresh()` 整页重画；
6. `drainSignals()`，每个信号排进 `Overlay` 演出队列（全屏转场、战斗动画、突破演出…）；
7. 演出放完后再播"获得反馈"：数值浮动提示（toast）、图标飞向状态栏、数字滚动。

不改状态的界面操作（切分类、调数量）走 `refresh()`，不存档。

### 3.4 多页签 = 多相机 + 世界坐标偏移（重要技巧）

`ScrollView`（`src/render/ui.ts`）：每个可滚动区域的内容放在**远离主界面的世界坐标**（例如 x = 10000、20000、50000），由一台**单独的相机**显示，相机的 viewport 就是这块区域在屏幕上的位置，自然实现裁剪。

- 切页签 = 切换哪台相机可见（`cam.setVisible`），不销毁对象；
- 滚动 = 改这台相机的 `scrollY`，在 `pointermove` 里按位移拖动，滚轮也支持；
- 全屏演出（`Overlay`）同理放在另一个偏移位置、用自己的相机盖在最上层。

好处：不需要 Mask（Mask 在手机上很贵），裁剪是相机 viewport 自带的。

**副作用（写自动化脚本时要注意）**：一个对象的屏幕坐标要先找到"照得到它的那台可见相机"再换算，不能只用主相机。见 `scripts/rec-drive.mjs` 里的 `PROJECT`。

### 3.5 性能铁律：不用 Graphics / Shape

真机实测（Adreno 750 / Android WebView 140）：Phaser 的 `Graphics` 和 `add.rectangle` 等 Shape 走另一条渲染管线，和文字、图片交替绘制时每次都切着色器程序。主界面 **201ms 一帧、229 次 `useProgram`**；全部换成纹理后 **16ms、7 次**。

做法（`src/render/ink.ts`，**可直接复制再改**）：

- 启动时用 Canvas 2D 一次性画出一套**白色**纹理：宣纸纹、毛笔笔触、墨晕、远山、圆角按钮、双线边框、圆环、实心圆、渐变、菱形、光斑……
- 用的时候 `setTint(颜色)` 上色，主题切换照常生效；纯色块用 Phaser 自带的 `'__WHITE'` 1×1 白图 + `setDisplaySize` + `setTint` 代替 `fillRect`。
- 可拉伸的框用 `NineSlice`。**坑**：NineSlice 的 3 段式（上下或左右切片为 0）高度被锁死在纹理高度、只能横向拉伸，所以胶囊条按高度各生成一张纹理并缓存（`pillTex` / `vpillTex`）。纹理还没生成时别用 NineSlice，用 `Image + setDisplaySize`。
- 画圆角不要用 `ctx.roundRect`（老 WebView 没有），自己用 `arcTo` 画。
- 程序纹理的随机性用固定种子的 `Rng`，每次启动画出来一样。

全项目 `grep add.graphics` 应为 0。新游戏从第一天就遵守，别等真机卡了再改。

### 3.6 文字

- `makeText()`（`ui.ts`）统一建文字：字体栈 `"PingFang SC","Microsoft YaHei","Noto Sans SC","Source Han Sans SC",sans-serif`；**`resolution: Math.ceil(zoom*2)/2`**，按物理像素渲染，高分屏不发虚。
- 字号用设计坐标（正文 30、小字 26、标题 34），再乘设置里的字号倍数（1 / 1.15 / 1.3）。按钮里的字号放大有上限，避免溢出。
- **中文换行**：Phaser 自带的换行按空格分词，对中文无效。`src/render/wrap.ts`（**可直接复制**）实现逐字换行 + 避头尾标点 + 连续字母数字不拆开，通过 `wordWrap.callback` 挂进 Phaser。

### 3.7 主题与设置

- `theme.ts`：`COLORS` / `TEXT_COLORS` 是**同一个对象原地 `Object.assign` 替换**，各处引用不变即可拿到新值；切换主题后重启场景让已创建的对象重新着色。
- `settings.ts`：全局单例，启动时读、改了立即存；字号、文字出现方式（逐字/逐行/立即）、昼夜主题、音乐、音效、演出开关、个性化广告开关。

### 3.8 按钮

`Button`（`ui.ts`）：底色 Image + 毛笔框 NineSlice（按两倍尺寸拉伸再缩小一半，笔触变细、质感保留）+ 可选图标 + 文字。**点击在抬起时判定，且手指移动不超过阈值**，避免滑动列表时误触。提供 `setEnabled`、`setPrimary`、`pulse()`（弹一下）。

### 3.9 素材加载与降级

- `src/data/assets.json` 是素材清单（key → 路径），由素材脚本生成。**清单里有的才加载，没有的用程序画的替代**（`hasImage(scene, key)` 判断）。所以美术没到位时游戏照样能跑。
- 加载页自己的主视觉和标题字用 Scene 的 `pack` 先加载；其余图片在加载页 `preload` 里加载；**音频进游戏后在后台加载**（音效先、BGM 后），不阻塞启动。
- 单个素材加载失败只打警告，按"没有这个素材"处理。
- 加载进度按"已完成文件数 + 正在下载文件的字节占比"计算，显示值追赶目标值，不会一格一格跳。

### 3.10 音频

`audio.ts` 是全局单例（用 `game.sound`，跨场景持续）：

- BGM 切换淡入淡出；大场面（标题、渡劫、死亡）立即切，日常曲目至少播 45 秒才换，新请求要稳定 3 秒才生效（只进某页看一眼不换曲）。
- 曲目素材缺失时有退路映射（`BGM_FALLBACK`）。
- 安卓切后台时暂停全部声音、回来恢复。

## 4. 平台层（src/platform）

### 4.1 接口

```ts
export interface Platform {
  name: 'web' | 'wechat';
  storage: { get(k): string | null; set(k, v): void; remove(k): void };
  screen(): { width: number; height: number; dpr: number };   // CSS 像素
  safeInsets(): { top: number; bottom: number };              // CSS 像素
  promptText(title: string, initial: string): Promise<string | null>;
  ads: AdProvider;
}
export interface AdProvider {
  rewardedReady(slot: string): boolean;
  showRewarded(slot: string): Promise<'rewarded' | 'closed' | 'unavailable'>;
  showInterstitial(): Promise<void>;
}
```

游戏代码只依赖这个接口。新平台 = 新写一个实现。

### 4.2 各平台实现

| 平台 | 存储 | 输入框 | 广告 | 其它 |
| --- | --- | --- | --- | --- |
| 浏览器 | localStorage | `window.prompt` | 模拟广告（`fakeAds.ts`，开发用） | 宽屏裁成 9:16 |
| 安卓（Capacitor） | 同浏览器（WebView 的 localStorage） | 同浏览器 | 原生插件 TapADN；未配置时正式包"暂无视频"、调试包模拟广告 | `android.ts`：返回键两次退出、切后台存档并暂停声音 |
| 微信小游戏 | `wx.getStorageSync` | `wx.showKeyboard` | 待接（返回 unavailable，按钮置灰） | 安全区要避开右上角胶囊按钮 |

**规则：模拟广告绝不能带进正式包。**正式包里没配置真广告就当"没有广告"，相关按钮置灰显示"暂无可用视频"，游戏流程不受影响。

### 4.3 广告业务规则放在逻辑层

`src/core/ads.ts`（纯逻辑，时间由外部传入）：每个激励广告位每天上限、插屏间隔与每日上限、新玩家前 30 分钟不出插屏、当天看过激励视频的插屏减半。账本存在跨局存档里，按自然日清零。模拟器可以开"每次都看广告的玩家"，核对广告不会把难度打崩。

## 5. 安卓打包（Capacitor）

### 5.1 一条命令出包

`scripts/build-android.mjs`：`npm run build` → `npx cap sync android` → Gradle `assembleRelease`/`assembleDebug` → 复制到 `dist-android/<name>-<version>-<variant>.apk`。

- JDK / Android SDK 直接用 Unity 自带的那套（`D:/unity/6000.0.23f1/Editor/Data/PlaybackEngines/AndroidPlayer/OpenJDK`），可用 `ANDROID_JAVA_HOME` 覆盖。**只读使用，不要往 Unity 安装目录里写东西。**
- **项目路径含中文时，Windows 下要用绝对路径调用 `gradlew.bat`**，否则 cmd 找不到。
- 正式签名读 `android-keys/keystore.properties`（目录在 .gitignore 里）；缺了只能打调试包。
- 调试包构建时设 `VITE_DEBUG_GAME=1`，`main.ts` 据此把 `window.__game` 暴露出来，方便真机 DevTools 量性能、自动化驱动；**正式包不暴露**。
- `capacitor.config.json` 的 `android.backgroundColor` 设成游戏底色，启动时不闪白。

### 5.2 原生插件

`android/app/src/main/java/<包名>/` 下自写 Capacitor 插件（`TapTapPlugin.java`、`TapAdPlugin.java`），JS 侧 `registerPlugin<接口>('名字')` 调用。凭证从 `android-keys/*.properties` 在 Gradle 构建时注入，不进代码库。没有凭证文件时 JS 侧拿到"未配置"，自动走降级路径——这让没有凭证也能打包测试。

### 5.3 国内上架的合规要点（踩过、已过审要求）

1. **首屏是隐私政策弹窗**，有明确的"同意"和"不同意"；不同意 → 再确认 → 可退出。同意记录带版本号（`LEGAL_VERSION`），政策改了改版本号，所有玩家重新同意。
2. **所有第三方 SDK 只在同意之后初始化**。注意 SDK 的 `ContentProvider` 会在进程启动时自动运行——要反编译确认它们只存 Context、不采集、不联网。验证方法：`pm clear` 后冷启动，在同意页停住，看 logcat 有无网络请求和敏感 API 调用。
3. **不申请任何运行时危险权限**最省事。广告 SDK 自带的"读取应用列表"等权限在 `AndroidManifest.xml` 里用 `tools:node="remove"` 去掉；广告 SDK 的采集开关（位置、电话状态、Wi-Fi、MAC、传感器/摇一摇、应用列表）在初始化时逐项关掉。
4. 隐私政策里列出每个 SDK 的名称、公司、用途、收集的字段、隐私政策链接；游戏内设置里提供"个性化广告"关闭开关和"退出登录"入口。
5. 签名换过要同步到 SDK 后台（MD5），否则登录报签名不符。

## 6. 素材流水线（AI 生成）

```
art-src/prompts.json      提示词：公共前缀/后缀片段 + 按类别（区域、立绘、图标、事件插图…）的模板与条目
   │  scripts/genimage.py / genbatch.py   调图像接口出原图，每次生成写入 art-src/generation_log.jsonl（版权留档）
   ▼
art-src/<类别>/<id>.png   原图（进版本库）
   │  npm run assets（scripts/assets.py）  按规格裁剪、压缩；音频用 ffmpeg 去首尾静音、统一响度（BGM -16 LUFS，音效峰值 -3dB）
   ▼
public/assets/...         成品  +  src/data/assets.json 清单
```

### 6.1 图像生成接口

**接口**：OpenAI 兼容的图像生成接口（走中转站），纯标准库 `urllib` 调用，不依赖 SDK。

| 项 | 值 |
| --- | --- |
| 地址 | 服务根地址 `https://api.aigocode.dev`；文生图 `POST /v1/images/generations`；图生图/遮罩编辑 `POST /v1/images/edits` |
| 模型 | `gpt-image-2.5-sunburst` |
| 鉴权 | `Authorization: Bearer <key>`，key 从项目根目录 `gpt_image_2_5_key.txt` 读取 |
| 请求体 | `{"model": ..., "prompt": "...", "size": "1536x1024", "quality": "high", "n": 1}` |
| 返回 | `data[0].b64_json`（base64 解码即 PNG）；没有时取 `data[0].url` 再下载 |
| 超时 | 生成 300 秒，下载 120 秒 |
| 重试 | 最多 3 次，间隔 5 / 10 秒；**4xx（提示词被拒、参数错）不重试**，5xx 和网络错误才重试 |

常用尺寸：区域横图、事件插图 `1536x1024`；立绘、加载页主视觉 `1024x1536`；图标、头像 `1024x1024`。

**key 的规矩**：key 文件加进 `.gitignore`，**永远不要打印、不要提交、不要贴进对话**。读的时候只 `read_text().strip()`。

**中转站会间歇性 503**：批量脚本"已存在的跳过"，所以失败后直接重跑同一条命令即可续上；必要时让后台每隔几分钟重跑一次。

**版权留档**：每生成一张，往 `art-src/generation_log.jsonl` 追加一行 `{file, model, api, size, quality, prompt, time}`。上架、软著、侵权申诉时用得上。

### 6.2 两个脚本

**单张 / 挑选候选**：`scripts/genimage.py`

```bash
python scripts/genimage.py <输出路径> <尺寸> "<提示词>" [张数]
python scripts/genimage.py art-src/regions/qingshi_village.png 1536x1024 "..." 3
```

张数大于 1 时文件名后加 `_1`、`_2`…，人挑好后改名为正式文件名。适合调风格、试提示词。

**批量**：`scripts/genbatch.py`（从 `genimage.py` 导入 `generate()`）

```bash
python scripts/genbatch.py                 # 生成 prompts.json 里所有缺图的条目
python scripts/genbatch.py icons vignettes # 只生成某几个类别
python scripts/genbatch.py --redo id1,id2  # 强制重画指定条目，旧图移到 art-src/_rejected/ 留底
```

- 4 线程并发（`CONCURRENCY = 4`），单张失败不影响其它，最后列出失败清单、返回码非 0。
- 输出路径固定为 `art-src/<类别 folder>/<条目 id>.png`，和素材处理脚本、游戏里的素材 key 一一对应。
- Windows 控制台默认 GBK，打印 ✓ 会抛异常、打断日志写入，所以脚本开头 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`。

### 6.3 提示词清单 `art-src/prompts.json`

```jsonc
{
  "fragments": {
    "pre":  "A traditional Chinese ink wash painting (shuimo) on aged off-white rice paper, loose xieyi brushwork ..., NOT a photograph, NOT digital art, NOT 3D.",
    "post": "Mostly monochrome black and grey ink ... No text, no calligraphy, no characters, no seal, no signature, no border."
  },
  "categories": {
    "regions": {
      "folder": "regions",
      "size": "1536x1024",
      "template": "{pre} Subject: {subject} Large areas of blank paper, soft mist. {post}",
      "items": [
        { "id": "qingshi_village", "subject": "a small mountain village at the foot of hills, ..." }
      ]
    }
    // icons、vignettes（事件插图）、enemies、portraits、realms、endings、ui …
  }
}
```

- 最终提示词 = `template.format(subject=条目主题, **fragments)`。**风格只写在 `fragments` 和 `template` 里，条目只写画什么**，几百张图才能风格统一。
- 提示词用英文写效果更稳；明确写出"不要文字、不要印章、不要边框"，否则模型很爱自己加落款。
- 新游戏换风格时只改 `fragments`，再 `--redo` 几张试看，满意了再批量。

### 6.4 其它

- 内容校验测试会检查"每件物品都有图标提示词"，避免加了物品忘了出图。
- 应用图标：`scripts/make_icon.py <方图.png>` 生成安卓各档 `ic_launcher` / `ic_launcher_round` / 自适应前景（画面缩到 78% 居中、边缘淡出），并把自适应背景色改成图片纸色。

## 9. 踩过的坑（按领域）

**Phaser**
- 场景的 `update()` 要等 `create()` 之后才调用；加载中要逐帧动画，监听 `Phaser.Scenes.Events.UPDATE`。
- `create()` 之后再 `load.start()` 加载音频，会触发 `progress` 把加载条打回 0；收尾后要忽略进度事件。
- Graphics/Shape 真机卡顿、NineSlice 3 段式高度锁死，见 3.5。
- 相机 `setOrigin(0,0)` 时 `worldView` 不适用，坐标换算直接按 `cam.x + (worldX - cam.scrollX) * cam.zoom`。

**Windows 开发环境（Git Bash）**
- `adb shell` 后面带 `/sdcard/...` 这类路径会被 MSYS 改写，要 `MSYS_NO_PATHCONV=1`。
- Node 的 ESM `import('/d/...')` 会解析成 `C:\d\...`；临时脚本放进项目目录，用相对路径导入。
- 项目路径含中文：gradlew 用绝对路径；Python 输出中文到控制台会乱码，不影响结果。

**Playwright / CDP**
- `page.evaluate(字符串, 参数)` 不会把参数传进去；要传函数，或把函数源码作为参数再 `eval`。

**安卓与上架**
- 改了 legal 文本一定要重新打包再交，曾经交过一个比隐私政策旧的 APK。
- 换签名后旧包无法覆盖安装（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），先卸载。
- 冷启动合规测试前先 `pm clear`，否则残留的"已同意"会造成假阳性。

**真机性能**
- 一定在真机上量，不要信桌面浏览器。调试包暴露 `window.__game`，用 DevTools 看每帧耗时和 `useProgram` 次数。

## 12. 新游戏不是文字游戏时怎么改

> 本节是**建议**，原项目是回合制文字游戏，下面的实时类做法**没有在原项目里实现和验证过**。照做之前先在新项目里用真机量一遍。

### 12.1 不变的部分

三层分离、平台层、安卓打包与合规、微信适配、AI 出图流水线、种子随机数、存档兼容、"不用 Graphics"的性能规则、多相机滚动列表、按钮、中文换行、音频管理、测试与真机自动化——**全部照用**。

### 12.2 主循环：逻辑层改成固定步长

回合类是"玩家点一下 → 逻辑算一步"；实时类是"每帧都要算"。逻辑层仍然保持纯 TypeScript、不碰 Phaser：

```ts
// core：纯逻辑，可以在 Node 里跑
interface InputState { moveX: number; moveY: number; fire: boolean }   // 每帧由界面层填
class World {
  constructor(public state: WorldState, content: Content) {}
  step(dt: number, input: InputState): void { /* 移动、碰撞、伤害、刷怪、计时；产出信号 */ }
  drainSignals(): Signal[] { /* 命中、死亡、拾取、升级…… */ }
}

// render：Phaser 场景里用累加器按固定步长推进
const STEP = 1 / 60;
update(_t: number, deltaMs: number) {
  this.acc += Math.min(deltaMs / 1000, 0.25);          // 卡顿时别一次补太多步
  while (this.acc >= STEP) { this.world.step(STEP, this.input); this.acc -= STEP; }
  this.syncSprites();                                  // 按 state 摆精灵位置
  for (const s of this.world.drainSignals()) this.playSignal(s);
}
```

- **固定步长**让同样的种子 + 同样的输入序列得到同样的结果：可以录制回放，可以在 Node 里无画面地跑模拟（bot 每步填 `InputState`）。
- 碰撞简单时（圆形、矩形）直接在 core 里写；需要复杂物理时可以用 Phaser Arcade Physics，但那样移动就跟引擎绑在一起了。这时**至少把规则**（伤害、掉落、波次、经验、经济）留在 core，保住数值模拟。
- 不要每帧存档。改成过关、结算、切后台（`hidden` 事件）、退出时存。
- 帧率改回 60：`fps: { target: 60 }`，去掉 `limit: 30`。

### 12.3 渲染

- **图集（texture atlas）**：精灵都打进少数几张大图里，同一张图的精灵能合批绘制。思路和 3.5 一样：少切换纹理、少切换着色器。
- **对象池**：子弹、敌人、特效反复出现，用 `Group`（设 `maxSize`）配合 `setActive/setVisible` 复用，别频繁 `create/destroy`。
- **频繁变化的数字**（分数、血量、伤害飘字）：普通 `Text` 每次 `setText` 都要重新画一张 canvas 纹理并上传，帧帧改很贵。改用 `BitmapText`（位图字体），或者降低刷新频率。
- 粒子用 Phaser 自带的粒子发射器，粒子纹理也走 3.5 的白纹理 + 着色。
- 横屏游戏：设计坐标改成固定高度（例如高 750），安卓在 `AndroidManifest.xml` 的 Activity 上设 `android:screenOrientation`，微信在 `game.json` 里设 `deviceOrientation`。
- 操作：虚拟摇杆、多点触控（`this.input.addPointer(2)`）。按钮仍然"抬起时判定"，但射击、跳跃这类动作要在按下时就触发。

### 12.4 素材

- 精灵需要**透明背景**。图像接口不一定能直接出透明图：可以在提示词里要求"主体单独放在纯色背景上"，再在 `assets.py` 里抠掉背景色、裁到内容边界、拼进图集。
- AI 很难画出**多帧动画里前后一致**的角色。优先用少帧数 + 补间（缩放、旋转、抖动、闪白）做动作感；必须逐帧时，考虑骨骼动画或手工修图。
- 风格统一仍然靠 `prompts.json` 的公共片段。

### 12.5 测试

- 模拟：无画面地跑 `World.step`，bot 按简单策略填输入，统计通关率、平均存活时间、经济曲线。
- 不变式：随机输入跑上万步，每步检查血量不为负、数量不越界、实体数量不爆炸。
- 真机：一定量**最多实体同屏**时的帧耗时，不要只量空场景。
